# 限制与统计

限制分几级：全局、客户端、隧道、域名转发，任意一级达到上限都会拒绝。网页里设置的位置见[管理页面说明](/reference/web-ui.md)。

网页表单里的“流量限制”“时间限制”“带宽限制”“最大连接数”“最大隧道数”这几个输入框，要在 `nps.conf` 里打开对应开关才会显示：

| 开关 | 控制的输入框 |
| --- | --- |
| `allow_flow_limit` | 流量限制 |
| `allow_time_limit` | 时间限制 |
| `allow_rate_limit` | 带宽限制 |
| `allow_connection_num_limit` | 最大连接数 |
| `allow_tunnel_num_limit` | 最大隧道数 |

初始配置文件里它们都是 `true`。配置键的默认值见[服务端配置](/reference/server-config.md)。

## 流量限制

可以给客户端、隧道和域名转发设置流量上限，单位 MB（客户端表单里可选单位）。达到上限后拒绝服务：域名转发返回错误页，其他转发拒绝连接。留空为不限。

### 流量统计方式

全局、客户端、隧道和域名转发各级流量都按**单侧**统计：

- **入口流量**：访问者发往客户端的字节；
- **出口流量**：客户端返回访问者的字节；
- **上下行流量**：两者之和，每个字节只计一次。

统计的是转发的内容，不含加密、压缩和多路复用的开销，也不含客户端与服务端之间的心跳等控制流量。每个转发的字节都要经过“访问者 到 服务器”和“服务器 到 客户端”两段，服务器实际消耗的流量约为上下行流量的两倍，列表中的**实际消耗**就是上下行流量乘 2。

客户端的流量限制默认按上下行流量判断。`nps.conf` 设置 `flow_limit_type=actual` 后，客户端的限制改按实际消耗判断，同样的限制值能用的上下行流量减半。隧道和域名转发的限制始终按上下行流量判断。

统计数据按 `flow_store_interval`（分钟，初始配置为 `1`，`0` 不持久化）保存。

## 带宽限制

- 客户端带宽限制（`rate_limit`，KB/s）：入口和出口合计的速度上限。
- 隧道、域名转发的限速：上行、下行分别设置，单位 KB/s（1 KB/s = 1024 B/s），`0` 不限。上行指访问者到目标服务，下行指目标服务到访问者。同一条目的所有连接共用各自方向的额度，同时还受客户端的带宽限制和全局带宽限制约束。npc 配置文件里用 `upload_limit`、`download_limit` 设置，见[npc 配置文件](/reference/npc-config.md)。
- 全局带宽限制：在“全局参数”页设置（KB/s，`0` 不限），所有客户端转发流量合计不超过它，修改后对已建立的连接立即生效。不受 `allow_rate_limit` 影响。

“客户端”列表上方显示服务端的转发总流量和当前速率：**流入**是访问者发往客户端的流量，**流出**是客户端返回访问者的流量。统计会持久化到 `conf/global.json`；点“清空流量”会同时清零。

点对点直连的流量不经过服务端，不计入服务端统计，也不受服务端限速影响。点对点访问隧道的流量限制用完时只停止中转，已建立的直连不受影响；流量清零或限额提高后自动恢复中转。

## 时间限制

到期日期，到期后拒绝连接。日期格式随便写，自动识别（支持时间戳，注意系统时区），留空为不限。例如 `2027-01-01`；指定东八区写 `2027-01-01 00:00:00 +0800 CST`。

## 连接数限制

- **客户端最大连接数**：对该客户端下的 SOCKS5、HTTP 代理、域名转发、TCP、UDP、点对点访问生效。
- **隧道、域名转发最大连接数**：`0`（默认）不限，与客户端的限制同时生效。计数方式：TCP、混合代理按访问连接，UDP 按活跃转发会话，SOCKS5 UDP 跟随它的 TCP 控制连接，域名转发的 HTTP 按并发请求、HTTPS 透传和 TLS 终止按连接。达到上限拒绝新连接，已有连接不受影响，断开后释放名额。点对点访问经服务端中继的连接同样受限，直连不受限。
- **全局最大转发连接数**：在“全局参数”页设置，`0` 不限，页面同时显示当前占用数；设置保存在全局数据文件中，重启后保留。计数口径同上；npc 控制连接、管理网页和点对点直连不计入。降低上限不会断开已有转发。

## 客户端最大隧道数

给客户端设置“最大隧道数”，限制它名下能创建的隧道数量。
