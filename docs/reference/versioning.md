# 版本规则与兼容范围

## 版本号规则

从 0.35 起，版本号 `主版本.次版本.修订版本` 的含义如下：

| 位 | 含义 |
| --- | --- |
| 主版本 | 是否还能连接旧客户端（范围见下文）。不再兼容连接时升主版本，在此之前会先发布 `0.99.x` 过渡版本 |
| 次版本 | 可以改变非核心功能；核心功能只在有条件兼容时才改变。相邻次版本的客户端必须能够连接 |
| 修订版本 | 保持兼容 |

建议不要跨越过多版本一次升级，升级前阅读 [CHANGELOG](https://github.com/djylb/nps/blob/master/CHANGELOG.md)。升级步骤见[升级到 0.35](/guide/server/upgrade.md)。

## 0.34 及更早的 npc 的兼容范围

0.35 的 nps 只对 0.34 及更早的 npc 承诺下表第一行，其余不作保证，升级前请确认：

| 级别 | 范围 |
| --- | --- |
| 保证 | 通过 `tcp`、`tls` 连接服务端；TCP 隧道；更新功能（见下文） |
| 尽量兼容，不保证 | 通过 `kcp`、`quic`、`ws`、`wss` 连接服务端（`quic`、`ws`、`wss` 需要 npc 0.33 及以上）；点对点访问 |
| 不再保证 | 其他隧道，如 UDP、域名解析、SOCKS5、HTTP 代理、文件等，能用不代表后续版本继续可用 |

“能连上”还取决于服务端监听的端口怎么配：混合端口 `mix_port` 对 0.34 及更早的 npc 的接受范围见[升级到 0.35](/guide/server/upgrade.md)。

### 协议版本

`npc -version` 输出的 `Core version` 是协议版本。0.35 的 nps 支持的协议版本是 `0.26.0` 到 `0.34.0`，可连接的最低版本由 `nps.conf` 的 `secure_mode` 决定：

| `secure_mode` | 可连接的最低协议版本 |
| --- | --- |
| `true`（发布包自带的配置） | `0.33.0` |
| `false` | `0.26.0` |

nps 启动时在日志的 `started` 事件里用 `min_client_version` 写出当前允许的最低版本，网页仪表盘的“最低支持版本”也显示它。协议版本低于 0.33 的 npc 只有在 `secure_mode=false` 时才能连接。

0.35 的 npc 不能连接旧版服务端，请先升级服务端。

### 依赖 npc 版本的功能

能连接不代表所有功能可用：

| 功能 | 要求的 npc |
| --- | --- |
| 服务端下发的健康检查 | 0.35.0 及以上；更旧的 npc 不会收到检查，服务端继续接受它按自身配置发来的上报 |
| 网页远程更新客户端 | 0.34.9 及以上；更旧的 npc 需要在客户端上手动更新 |
| 点对点访问（访问端和提供端，中转与直连） | 0.35.0 及以上；更旧的访问端被拒绝，更旧的提供端只能被中转访问 |
| 同一 vkey 多个 npc 按实例路由 | 0.32 及以上；更旧的 npc 没有稳定的实例标识，按 `bridge_select_mode` 选择 |

## 从更旧版本更新到 0.35

0.34 及更早版本的 `update` 命令继续从发布页下载对应平台的压缩包，可以直接更新到 0.35。具体注意事项（0.34.8 以下网页文件的位置、0.26 版本线要求已执行 `nps install` 等）见[升级到 0.35](/guide/server/upgrade.md)。

## 更新通道

更新内容经过签名校验，通过的才会安装。新主版本发布后，0.x 仍能收到 0.x 的补丁并更新到其中最新的版本。更新不会跨主版本，需要手动升级。

0.34 及更早版本的更新仍从 `latest` 按文件名下载，所以 0.x 期间发布包的文件名和路径不会改变。
