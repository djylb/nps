# 版本规则与兼容范围

## 版本号规则

从 0.35 起，版本号 `主版本.次版本.修订版本` 含义如下：

| 位 | 含义 |
| --- | --- |
| 主版本 | 是否还能连接旧客户端（范围见下文）。不再兼容连接时升主版本，在此之前会先发布 `0.99.x` 过渡版本 |
| 次版本 | 可以改变非核心功能；核心功能只在有条件兼容时才改变。相邻次版本的客户端必须能够连接 |
| 修订版本 | 保持兼容 |

建议不要跨越过多版本一次升级，升级前阅读 [CHANGELOG](https://github.com/djylb/nps/blob/master/CHANGELOG.md)。

## 旧版 npc 的兼容范围

0.35 只对旧版 npc 承诺下表第一行，其余不作保证，升级前请确认：

| 级别 | 范围 |
| --- | --- |
| 保证 | 通过 `tcp`、`tls` 连接 bridge；旧版 TCP 隧道；更新功能（见下文） |
| 尽量兼容，不保证 | 通过 `kcp`、`quic`、`ws`、`wss` 连接 bridge（`quic`、`ws`、`wss` 需要 npc 0.33 及以上）；点对点访问 |
| 不再保证 | 其他隧道，如 UDP、域名解析、SOCKS5、HTTP 代理、文件等，能用不代表后续版本继续可用 |

发布前的连通性测试使用各旧版本线的最后一个版本（0.26.56 到 0.34.10，另含 0.34.8、0.34.9），不覆盖每个修订版本。

### 协议版本

`npc -version` 输出的 `Core version` 是协议版本。当前支持的协议版本为 `0.26.0` 到 `0.34.0`：

| `nps.conf` 设置 | 可连接的最低协议版本 |
| --- | --- |
| `secure_mode=true`（示例配置） | `0.33.0` |
| `secure_mode=false` | `0.26.0` |

服务端启动日志会打印当前允许的最低版本。低于 0.33 的 npc 只有在 `secure_mode=false` 时才能连接。

新版 npc 只使用最新协议，不能连接旧版服务端；请先更新服务端。

### 从旧版更新到 0.35

旧版的 `update` 命令继续从发布页下载对应平台的压缩包，可以直接更新到 0.35；0.35 之后的更新改用签名的发布清单。

- 0.34.9 及以上的 npc 还可以由服务端发起远程更新；更旧的 npc 会收到“不支持远程更新”的提示，需要在客户端上手动更新。
- 0.34.8 以下的 nps 把网页文件更新到安装目录（Linux 为 `/etc/nps`）。没有安装、直接在解压目录运行时，那里的网页文件不会更新，管理页面可能报错，隧道不受影响；此时请用发布包中的 `web` 目录手动覆盖。
- 0.26 版本线只替换系统目录（如 `/usr/bin`）中的程序，且要求已经执行过 `nps install`；未安装时 nps 的 `update` 会失败，请手动替换。

### 依赖 npc 版本的功能

能连接不代表所有功能可用：

| 功能 | 要求的 npc |
| --- | --- |
| 服务端下发健康检查 | 0.35.0 及以上；更旧的 npc 不会收到检查，服务端继续接受它按自身配置发来的上报 |
| 网页远程更新客户端 | 0.34.9 及以上 |
| 点对点访问（访问端和提供端，中转与直连） | 0.35.0 及以上；更旧的访问端被拒绝，更旧的提供端只能被中转访问 |
| 多实例按实例路由 | 0.32 及以上；更旧的 npc 没有稳定的实例标识，按 `bridge_select_mode` 选择 |

## 更新通道

所有版本读取同一份固定位置的发布清单（`channel` 发布下的 `manifest.json`），不依赖 `latest`。清单累积各主版本的发布，所以新主版本发布后，0.x 仍能收到 0.x 的补丁并更新到其中最新的版本。是否允许跨主版本由清单规则决定，规则见仓库的 `release/update-rules.json`，目前不允许，需要手动升级。

旧版更新到 0.35 仍从 `latest` 按文件名下载，所以 0.x 期间发布包的文件名和路径不会改变。

## 1.0 不原样保留的能力

1.0 是重新设计的版本。以下 0.35 新增的能力不会原样保留，依赖它们的脚本和配置届时需要调整：

| 能力 | 到 1.0 的结果 |
| --- | --- |
| `npc -launch` 的 JSON、YAML、INI 配置和远程下发 hosts、tasks | 取消，没有迁移路径 |
| 同一 vkey 的多实例按实例路由 | 取消，不同目标改用多个成员 |
| Webhook 的事件名和负载 | 改变，接收方需要重写 |
| 全局 `visitor_vkey` | 改为按客户端签发的凭据，需要重新签发 |
| 全局登录名单 `login_acl_*` | 改为按用户配置，迁移时转换 |
| 配置导出文件 | 只用于 0.x 之间搬配置，不是迁移到新大版本的途径 |
