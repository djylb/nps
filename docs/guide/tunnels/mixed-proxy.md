# 混合代理

## 这能解决什么

在公网服务器上开一个代理端口，同一个端口同时提供 HTTP 代理和 SOCKS5 代理，两者可以分别开关。把电脑或浏览器的代理指向它，就能像连了 VPN 一样访问内网机器上的任意设备和资源，访问的出口是内网机器上的 npc。

示例：把 `203.0.113.10:8003` 作为代理。

## 操作步骤

1. 左侧菜单点“混合代理”，点“新增”。
2. 填写：
   - 客户端 ID：出口所在的内网机器上的客户端；
   - 服务端端口：`8003`；
   - “混合代理”一栏里勾选“启用 HTTP 代理”“启用 Socks5 代理”（默认都勾选）；
   - “账号认证”里的“密码认证”：每行 `用户名=密码`，例如 `user1=pass1`。
3. 点“新增”，并在服务器防火墙放行 TCP `8003`。

代理端口对公网开放，**务必设置账号认证**，也可以用 IP 白名单限制来源。来源名单在握手和认证之前检查。

## 怎么验证

```bash
curl -x http://user1:pass1@203.0.113.10:8003 http://192.168.1.10/
curl -x socks5h://user1:pass1@203.0.113.10:8003 http://192.168.1.10/
```

两条都能返回内网机器的响应即可（只启用了其中一种协议时，只测对应的一条）。`socks5h` 表示域名也交给代理解析。日常使用时，在浏览器、系统代理，或 Proxifier 这类全局代理工具里填写地址 `203.0.113.10`、端口 `8003` 和账号。

## 常见选项

- **目标访问控制**：限制这个代理能访问哪些目标。选“白名单”则只能访问名单内的目标，选“黑名单”则不能访问名单内的目标，选“关闭”不限制。对 HTTP 请求、HTTP CONNECT、SOCKS5 的 TCP 连接，以及 SOCKS5 UDP 的每个数据报都生效，被拒绝的 UDP 数据报直接丢弃。“目标访问控制条目”每行一条，以 `#` 开头为注释：

  | 写法 | 含义 |
  | --- | --- |
  | `192.168.1.10`、`10.0.0.0/8` | IP 或网段 |
  | `full:example.com` | 精确匹配这个域名 |
  | `*.example.com` | 只匹配子域名 |
  | `*example.com`、`domain:example.com` | 匹配该域名本身和它的子域名 |
  | `keyword:google`，或不带前缀的 `google` | 域名包含这段文字 |
  | `regexp:^ads\.` | 正则匹配域名 |
  | `geosite:cn`、`geoip:cn` | Geo 数据中的域名、IP 分类 |

  保存时规则会统一成规范写法。
- **IP 黑名单、白名单、名单优先级、仅允许已登记的 IP**：限制谁能使用这个代理，见[访问控制](/guide/server/access-control.md)。
- **限制**：最大连接数、上行和下行限速、流量限制、时间限制，与 [TCP 隧道](/guide/tunnels/tcp.md)一致。

## 注意

通过 SOCKS5 访问时，nps 在收到数据之前就已经接受了连接，所以对代理端口做端口扫描会显示所有端口都开放，连上后很快被关闭。这是代理的正常表现，不代表内网端口真的开放。
