# 健康检查

TCP、Secret 隧道和域名的编辑页可以启用健康检查，并设置检查方式（TCP、HTTP、HTTPS）、路径、间隔（默认 10 秒）、超时（默认 3 秒）和失败阈值（默认 3 次）。启用后，服务端把检查列表下发给 npc（要求 npc 0.35.0 及以上），npc 只保存在内存中，重连后重新下发。UDP 隧道不支持。

- 只有目标超过 1 个时才会检查。
- 检查失败的目标不再分配连接，恢复后自动加入。
- TCP 检查：目标最近有成功的 TCP 连接时不额外探测，空闲时才按间隔探测。
- HTTP、HTTPS 检查按间隔探测，不会被真实流量推迟，只把 200 状态视为成功。HTTPS 检查不校验证书，只判断存活。
- 多个隧道或域名的检查相同时合并为一个，没有隧道或域名使用时停止。
- 客户端有多个实例时，Web 管理的条目由其中一个实例检查；配置文件注册的条目由各实例检查自己的目标。

配置文件注册的隧道和域名也可以在编辑页启用，但设置只在条目存在期间有效：客户端断开、条目被清理后需要重新启用。

0.35.0 起 npc 不再支持配置文件中的 `health_*` 配置节，遇到时忽略并告警。服务端继续接受旧版本 npc 按其配置发来的上报。

API 字段见 [Web API](/reference/web-api.md)。
