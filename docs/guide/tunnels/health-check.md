# 健康检查

## 这能解决什么

一条隧道或域名有多个目标时，让 nps 自动发现故障的目标，不再给它分配连接，恢复后再自动加回来，避免部分访问失败。

## 操作步骤

1. 编辑（或新增）一条 TCP 隧道，或一个域名转发。
2. “目标”里填写至少两个目标，每行一个，例如：

   ```
   192.168.1.10:80
   192.168.1.11:80
   ```

3. 在“后端设置”的“健康检查”里勾选“启用健康检查”，设置：
   - 检查方式：TCP、HTTP 或 HTTPS；
   - 检查路径：HTTP、HTTPS 时填写，例如 `/health`；
   - 间隔（秒），默认 10；
   - 超时（秒），默认 3；
   - 失败阈值（次），默认 3，连续失败达到这个次数才判为故障。
4. 保存。服务端把检查列表下发给 npc，要求 npc 为 0.35.0 或更新。

只有 TCP 隧道和域名转发有这一项，UDP 隧道、混合代理和点对点访问没有。

## 怎么验证

停掉其中一个目标的服务，等待“间隔 × 失败阈值”这么长的时间后重复访问几次，请求都应落在剩下的目标上；重新启动该服务后，它会被自动加回。

## 常见选项

- 只有目标超过 1 个才会检查。
- TCP 检查：目标最近有成功的连接时不额外探测，空闲时才按间隔探测。
- HTTP、HTTPS 检查：始终按间隔探测，只把 200 状态当作成功；HTTPS 检查不校验证书，只判断目标是否存活。
- 检查设置相同的多个隧道或域名会合并成一个检查；没有隧道或域名使用时，检查停止。
- 检查列表只保存在 npc 的内存里，npc 重连后重新下发。
- 同一个客户端运行了多个实例时，在网页上创建的条目由其中一个实例检查。
