# 虚拟后端

## 这能解决什么

有些服务不是内网里某台机器上的一个地址，而是 npc 自己在本机提供的，例如共享一个目录的文件服务（WebDAV，浏览器也能直接浏览）。这类服务叫虚拟后端：它不监听任何端口，只有 npc 在线时才存在，需要让其他隧道或域名把它当作目标，才能从外部访问。

好处是不必在 npc 所在机器上再开一个本地端口，也不必为它单独占用公网端口，可以直接复用 TCP 隧道或域名转发的访问控制、限速等功能。

## 操作步骤

### 1. 让 npc 提供虚拟后端

虚拟后端是 npc 的文件共享，在 npc 的配置文件里声明，字段见 [npc 配置文件参考](/reference/npc-config.md)。npc 连上 nps 后，会把它上报给服务端。虚拟后端不写入服务端的数据，npc 断开后就从列表里消失。

### 2. 在网页上找到它的目标

左侧菜单点“虚拟后端”，列表里有它所属的客户端 ID、备注、类型（文件共享显示为 FILE）、网络和目标。目标形如 `service://…`，点这一行“选项”里的复制按钮复制它。

### 3. 用它建一条隧道

要从公网访问，就把这个目标当作别的隧道的目标：

1. 左侧菜单点“TCP 隧道”，点“新增”。
2. “客户端 ID”选与这个虚拟后端相同的客户端。
3. 服务端端口填 `9100`；“目标 (IP:端口)”粘贴刚才复制的 `service://…`。
4. 点“新增”，并在服务器防火墙放行 TCP `9100`。

网络是 UDP 的虚拟后端不能用在 TCP 隧道上，反过来也一样，保存时会提示不匹配。文件共享是 HTTP 服务，也可以建一个[域名转发](/guide/tunnels/domain-forwarding.md)，目标填同样的 `service://…`，用域名访问。

## 怎么验证

在浏览器打开 `http://203.0.113.10:9100/`（文件共享在配置里设置了访问前缀时，加上这个前缀），能看到共享目录的内容。也可以用 WebDAV 客户端挂载同一个地址。

## 常见选项

- **目标服务不可用**：隧道列表里，目标是虚拟后端而 npc 当前没有上报它（npc 离线或停止了这个服务）时，这条隧道会标上“目标服务不可用”，访问会失败。npc 重新上线后自动恢复。
- **目标是固定的**：`service://…` 由类型和名称决定，名称不变，npc 重启后目标不变，隧道不用重新设置。
- **多个 npc 提供同名服务**：同一个客户端密钥下的多个 npc 提供同名服务时，连接会被送到其中一个。
- **访问控制**：账号认证在 npc 的文件共享设置里配置；IP 名单、限速、连接数在使用它的 TCP 隧道或域名上设置。
