# TCP 隧道

## 这能解决什么

把内网机器的某个 TCP 端口，映射到公网服务器的一个端口上。适合 SSH、远程桌面、数据库、内网网站（不想用域名时）等。

示例：通过 `203.0.113.10:8001` 连接内网 `192.168.1.10:22` 的 SSH。

## 操作步骤

1. 左侧菜单点“TCP 隧道”，点“新增”。
2. “客户端 ID”选内网机器上的客户端。
3. 在“监听与目标”里填：
   - 服务端端口：`8001`（留空则自动生成）；
   - 目标 (IP:端口)：`192.168.1.10:22`。
4. 点“新增”。
5. 在服务器防火墙放行 TCP `8001`。

## 怎么验证

```bash
ssh -p 8001 user@203.0.113.10
```

能看到 SSH 登录提示，说明隧道通了。连不上时先在公网服务器上执行 `nc -vz 127.0.0.1 8001`，确认端口已在监听，再检查防火墙。

## 常见选项

- **多个目标**：目标按行填写多个地址，连接会在它们之间分配，只有 TCP 隧道支持。可以配合[健康检查](/guide/tunnels/health-check.md)，让故障的目标不再分配连接。
- **端口范围**：“服务端端口”可以填 `8000-8100,9000` 这样的范围，每个端口新建一条隧道，备注自动加上端口号，全部成功才会创建。此时目标只能写一行：`192.168.1.10:22` 表示所有端口都转发到它，`192.168.1.10:8000-8100,9000` 则与监听端口一一对应。
- **服务端 IP**：服务器有多个网卡时，指定隧道只在哪个地址上监听（默认 `0.0.0.0`，全部地址）。这一项需要服务端开启 `allow_multi_ip`，见[服务端配置](/reference/server-config.md)。
- **代理到服务器本地**：选“是”后，目标由服务器自己去连，不经过 npc，目标可以只写端口号。需要服务端开启 `allow_local_proxy`，没开时网页上看不到这一项。
- **代理协议 (Proxy Protocol)**：目标服务需要看到访问者真实 IP 时，选“V1-字符串格式”或“V2-二进制格式”，前提是目标服务支持。
- **访问控制**：“IP 黑名单”“IP 白名单”“名单优先级”“仅允许已登记的 IP”，见[访问控制](/guide/server/access-control.md)。
- **限制**：“最大连接数”“上行限速”“下行限速”（单位 KB/s，0 为不限）“流量限制”“时间限制”，留空为不限制。
