# 访问控制与登录来源

这一页讲 nps 上控制“谁能连进来”的几种办法：限制谁能登录网页管理、按来源 IP 的黑白名单、要求访问者先登记 IP、限制隧道可用的端口。


## 登录来源名单

`login_acl_mode`、`login_acl_rules` 限制谁能登录和注册 Web 管理：

```ini
# 0 关闭（默认），1 白名单，2 黑名单
login_acl_mode=1
# 语法同全局名单，用逗号或换行分隔；没有规则时不限制
login_acl_rules=127.0.0.1,10.0.0.0/8
```

被拒绝的登录、注册请求返回 403，日志里是 `login_failed`（`reason=acl`）。它不影响已登录的会话，也不影响 IP 登记页面。修改后[重载](/guide/server/operations.md)即生效。

登录保护还包括验证码（`open_captcha`）、PoW（`pow_bits`）、TOTP（`totp_secret`）和失败封禁（`login_*`），见[服务端配置](/reference/server-config.md)。被封禁的来源可以在网页“封禁管理”页查看和解除，同一个页面也能清除所有记录。

## IP 黑白名单

可以按来源 IP 限制访问，分为三层：**全局**（全局参数页）、**客户端**（客户端编辑页）、**隧道或域名转发**（对应的编辑页，点对点访问除外）。访问需要依次通过这三层，任何一层拒绝即拒绝，上级拒绝的访问下级无法放行。

**全局名单相当于 nps 前面的防火墙**，对所有进入 nps 的连接生效：客户端连接、所有隧道和域名转发、Web 管理界面（包括登录页和 IP 登记页）。点对点打洞使用的 UDP 探测端口（`p2p_port`）不受全局名单限制：它只用于探测 NAT、不转发流量，而探测包的来源地址可能与客户端连接不同（多出口、IPv4/IPv6、经反代连接等），限制它容易导致打洞失败。被拒绝的地址连管理界面也无法打开，修改前请确认不会把自己挡在外面，误操作时可手动编辑 `conf/global.json` 恢复。限制谁能访问哪个内网服务，应在客户端或隧道、域名转发中配置。

每一层都可以同时配置“IP 黑名单”和“IP 白名单”，并用“名单优先级”选择优先级（黑名单优先、白名单优先，只在两个名单都写了时起作用）：

| | 只在白名单 | 只在黑名单 | 同时在两个名单 | 都不在 |
|---|---|---|---|---|
| 黑名单优先（默认） | 放行 | 拒绝 | 拒绝 | 拒绝 |
| 白名单优先 | 放行 | 拒绝 | 放行 | 放行 |

只配置一个名单时：只有黑名单则名单内的地址拒绝、其余放行；只有白名单则名单内的地址放行、其余拒绝。两个名单都为空时不做限制。

每行一条规则，`#` 开头为注释：

| 写法 | 含义 |
|---|---|
| `1.2.3.4`、`2001:db8::1` | 单个 IP |
| `10.0.0.0/8` | 网段 |
| `192.168.*`、`10.*` | IPv4 前缀通配 |
| `geoip:cn` | Geo 数据中的国家或地区 |
| `geoip:!cn` | 除该国家或地区以外 |
| `geoip:private` | 内网和保留地址（不需要 Geo 数据） |
| `ext-ip:文件名:代码` | Geo 数据目录下其他文件中的分类（仅全局名单可用） |

不支持 `1.1.1.1-1.1.1.5` 这类区间写法，请改用网段；前缀拼错（如 `geoipp:cn`）也会被判为无效。客户端、隧道和域名转发的名单每份最多 1000 条，可通过 `nps.conf` 的 `acl_max_rules` 修改（`0` 为不限制）。规则在保存时校验，有误时会提示具体行号，保存后统一为规范写法（例如 `10.1.2.3/8` 存为 `10.0.0.0/8`）。

### Geo 数据

`geoip:` 和 `geosite:` 规则使用 [Loyalsoldier/v2ray-rules-dat](https://github.com/Loyalsoldier/v2ray-rules-dat) 的 `geoip.dat` 和 `geosite.dat`。Docker 镜像已附带，二进制发布包不附带，需要先下载；默认位于 `conf` 目录，路径可通过 `geoip_path`、`geosite_path` 修改。

有文件才启用。`geosite.dat` 默认不下载，需要时更新一次即可；删除文件即关闭（已加载的名单可能要重启才释放）。

更新方式（两个文件可分别更新）：

- 在 Web 管理界面的全局参数页点击对应文件的更新按钮；
- 或执行 `nps update-geo geoip`、`nps update-geo geosite`，不带参数时更新 geoip 和已存在的其他文件（运行中的 nps 会在一分钟内自动生效）。更新结果在日志里是 `source_updated` 或 `source_failed` 事件。

文件缺失时，相关规则不生效并记录日志，其余规则照常生效：含这类规则的白名单不作限制，全部放行；黑名单中的这些规则不拦截。注意这是默认放行，依赖 Geo 规则做访问控制时请确认文件已下载。

## 仅允许已登记的 IP

如果把 SSH 这类风险较高的服务暴露在公网上，可以在**客户端、隧道或域名转发**的编辑页开启“仅允许已登记的 IP”。开启后，访问者除了要通过黑白名单，还必须先登记自己的 IP；只影响开启了的客户端或条目，不影响其他服务。没登记的访问在日志里是 `tunnel_denied`（`reason=not_registered`）。

**登记方式：**

**方式一：** 在需要访问的机器上运行 npc：

```bash
npc register -launch="npc://YOUR_VKEY@203.0.113.10:8024?type=tls" -time=2
```

链接里的 `YOUR_VKEY` 在网页“客户端”列表的“唯一验证密钥”处查看；`-time` 是有效小时数。用客户端的 vkey 登记时只对该客户端有效，用公钥（`public_vkey`）登记时对所有客户端有效。

**方式二：** 打开 IP 登记页面，输入客户端的**登记口令**或 vkey，即可为当前 IP 登记该客户端；输入公钥（`public_vkey`）则相当于管理员登录，对所有客户端有效。

- 登记页面的地址：
  - Web 管理界面的 `/ip/register`（配置了 `web_base_url` 时带上该前缀，例如 `/nps/ip/register`），登录页也有入口；
  - 在 `nps.conf` 中配置 `ip_register_port`（和 `ip_register_ip`）后，会在该端口单独提供登记页面，根路径即为登记页面，不暴露管理界面；同时配置 `ip_register_cert_file` 和 `ip_register_key_file` 时使用 HTTPS，否则为 HTTP；
  - 通过嵌套转发 `bridge://ipreg`，例如在域名转发中把目标设为 `bridge://ipreg`。
- “登记口令”在客户端编辑页设置（可一键生成），与 vkey 分开，泄露后重置即可，不影响客户端连接；编辑页还会显示“登记链接”，可直接发给访问者。
- 页面上可以选择有效期，超过上限时按上限登记。上限在客户端编辑页的“登记最长有效期（小时）”设置，未设置时以及使用公钥登记时，取 `nps.conf` 中的 `ip_register_max_hours`（默认 2 小时）。
- 登记页面与登录共用失败记录和封禁：输错口令计入失败次数，失败后需间隔一段时间才能再试，达到上限的 IP 登录和登记都会被暂时封禁；开启验证码时登记页面同样需要验证码。

**方式三：** 登录 Web 管理界面后自动为登录的 IP 登记两小时：管理员对所有客户端有效，普通用户只对自己的客户端有效。

登记只保存在内存中，nps 重启后需要重新登记。仪表盘会显示当前已登记的 IP 数量。

**注意：** 公网 IP 可能变化，同一网络下的多人也可能共用同一个公网 IP。

## 端口白名单

为了防止服务端上的端口被滥用，可以在 `nps.conf` 里用 `allow_ports` 限制隧道能开启的端口。不写或留空表示不限制，格式：

```ini
allow_ports=9001-9009,10001,11000-12000
```
